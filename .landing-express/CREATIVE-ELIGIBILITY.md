# Landing Express — Creative Decision Pipeline V1.3

This contract runs after editorial/style/visual interpretation has enough context and governs the creative path that precedes `CONCEPTION READY`.

The governing principle is:

> Interpret context first. Generate opportunities second. Select mechanisms last.

## 1. Thematic / Creative Eligibility

Infer the creative territory from product, context, audience, narrative, emotion and perceived intention.

When material, derive compactly:

```text
emotional field
cultural / visual territory
desired intensity
materiality
typography character
atmosphere eligibility
motion character
spatial character
interaction character
```

Mechanisms such as `smoke`, `light rays`, `particles`, `bold typography`, `3D`, `glow`, `parallax` and similar are eligible possibilities, never category defaults. `ELIGIBLE != SELECTED`.

Never reduce category to aesthetic preset. Products from the same domain may require different creative territories when positioning and intent differ. The user does not need to name the territory.

## 2. Creative Intensity Map

Represent creative intensity internally across visual, motion, atmospheric, typographic tension, spatial and interaction dimensions using contextual bands:

```text
LOW | MODERATE | HIGH | VARIABLE
```

Diagnose `CALIBRATED`, `UNDER_DESIGNED` or `OVER_INTENSE`. Creative intensity is independent from model/effort reasoning capability.

## 3. Opportunity Pass

Run an internal `OPPORTUNITY PASS` before readiness. It must not become another visible questionnaire.

Evaluate material opportunities across typography, composition, scale/contrast, asset value, atmosphere, depth/spatiality, motion, interaction, material/light, simplification/removal and mobile redesign.

Rules:

- do not wait for the user to name the technical solution;
- `NONE` is valid when an additional layer would only add noise;
- normally retain only the 2–5 highest-value material directions;
- expose only material recommendations/decisions;
- do not select an opportunity merely because it is visually impressive or technically sophisticated.

## 4. Creative Hypothesis

Before a mechanism becomes a material recommendation, formulate compactly:

```text
observation
→ hypothesis of elevation
→ expected impact
→ candidate mechanism
→ material trade-off
→ recommendation
```

Use `AUTO | RECOMMEND | COMPARE | NO_CHANGE`. Use `ASK` through Copilot Initiative when the decision changes intent, identity, priority, narrative or scope. Persist compact decision rationale, never private chain-of-thought.

## 5. Anti-Cliché Pass

After eligibility and before final selection ask internally:

> `Estou interpretando este universo ou apenas reproduzindo um clichê da categoria?`

Classify `PASS | REFRAME | COMPARE | REJECT`.

A familiar mechanism is not automatically invalid. Reject only generic/category-driven applications without contextual/editorial value. Reframe familiar mechanisms that need specificity. Compare obvious and more contextual alternatives when both are plausible.

## 6. Opportunity Prioritization

Rank internally as `HIGH_VALUE | MEDIUM_VALUE | LOW_VALUE` considering editorial impact, perceived premium uplift, asset value, narrative contribution, implementation cost, actual stack compatibility, responsive viability, performance risk and accessibility risk.

Prefer high value with reasonable cost/risk. Technical sophistication is never value by itself.

## 7. Cinematic Enrichment Pass

`CINEMATIC ENRICHMENT PASS` runs only when editorial/style/visual base is coherent enough, creative eligibility is resolved or explicitly non-material and creative intensity is resolved.

Never use cinematic enrichment to hide unresolved editorial contradiction.

Internal order:

```text
ASSET VALUE
→ ATMOSPHERE
→ DEPTH / SPATIALITY
→ MOTION DRAMATURGY
→ TYPOGRAPHIC IMPACT
→ INTERACTION OPPORTUNITY
→ RESPONSIVE CINEMATIC INTERPRETATION
→ OPPORTUNITY PRIORITIZATION
→ CINEMATIC BUDGET / INTENSITY CURVE
→ CINEMATIC CONTINUITY
→ PROACTIVE RECOMMENDATIONS
```

The pass asks:

> `O que ainda pode elevar a percepção de produção e valor cinematográfico desta experiência?`

The answer may be `NONE`. Specialized pass evidence must be valid before final prioritization.

## 8. Copilot-driven vs User-driven Enrichment

`COPILOT-DRIVEN ENRICHMENT` runs proactively before `CONCEPTION READY`, converges to selected opportunities or `NONE`, and does not consume user loops.

`USER-DRIVEN ENRICHMENT` begins at `Quer acrescentar algo antes de eu consolidar?`, follows `MINOR | ENRICHMENT | STRUCTURAL | SCOPE_SHIFT`, and owns the 0..3 material-loop budget.

## 9. Governing ordering

```text
USER INTENTION
→ EDITORIAL INTERPRETATION
→ STYLE / VISUAL INTERPRETATION
→ THEMATIC / CREATIVE ELIGIBILITY
→ CREATIVE INTENSITY MAP
→ ASSET ROLE + ASSET AFFORDANCE WHEN MATERIAL
→ OPPORTUNITY PASS
→ CINEMATIC ENRICHMENT
→ SPECIALIZED PASS EVIDENCE
→ CREATIVE HYPOTHESES
→ ANTI-CLICHÉ PASS
→ OPPORTUNITY PRIORITIZATION
→ CINEMATIC BUDGET + INTENSITY CURVE
→ CINEMATIC CONTINUITY
→ RESPONSIVE CINEMATIC INTERPRETATION
→ PROACTIVE RECOMMENDATIONS / MATERIAL USER DECISIONS
→ CONCEPTION READY
→ USER-DRIVEN ENRICHMENT 0..3
```

Context before mechanism, evidence before selection, specificity before selection, value before complexity.

## 10. Persistence

Persist only compact operational evidence in existing Conception State fields plus `creativeGovernance` metadata. Do not create a parallel mega-state.

Persist selected territory/intensity, opportunities, compact hypotheses, authority, specialized pass evidence, responsive interpretation, continuity motifs, intensity curve, motion dramaturgy and selected interaction rationale only when operationally useful.

Do not persist hidden chain-of-thought, verbose scores, speculative option dumps or rejected alternatives unless a compact rejection reason is operationally necessary.

## 11. Asset Value Pass

Classify material assets when useful as `HERO_ANCHOR | DETAIL | PROOF | ATMOSPHERIC | BACKGROUND | TRANSITION | DECORATIVE`.

`Asset placement != Asset utilization`.

Evaluate narrative/hierarchy/production contribution and proactively consider crop, close-up, scale shift, parallax, layer separation, reflection, lighting highlight, shadow treatment, masking/reveal, technical callouts, detail reuse, foreground/background transitions and scroll-driven transformation.

Reuse is valid when the same asset performs another narrative role. Repetition without function is not enrichment.

## 12. Asset Affordance

Before promising a treatment, evaluate crop, isolation/cutout, close-up/detail, parallax, silhouette, lighting treatment, pseudo-3D/depth, masking/reveal, technical callout and responsive reuse viability using:

```text
STRONG | VIABLE | LIMITED | NOT_VIABLE | UNKNOWN
```

Consider resolution, framing, background, proportion, transparency and perceptual quality. A treatment depending on `NOT_VIABLE` affordance must not reach final selection. Prefer alternative treatment before generated media.

## 13. Atmosphere Pass

Atmospheric repertoire may include smoke, haze, light rays, volumetric-like light, particles, glow, localized bloom, reflections, vignette, light leak, shadow depth, ambient gradients and noise/texture.

Every selected treatment requires perceptible/editorial function. Do not apply atmosphere globally just to make a page cinematic. Dynamic atmosphere must define mobile, reduced-motion and performance behavior.

## 14. Depth / Spatiality Pass

Evaluate foreground, middle ground, background, overlap, occlusion, scale, perspective, lighting separation and z-axis motion.

Choose the smallest mechanism capable of the approved effect:

```text
CSS_LAYERING
→ TRANSFORMS_PARALLAX
→ SVG_MASKING_CLIPPING
→ CANVAS
→ R3F_THREE
→ SHADER_CUSTOM_WEBGL
```

Cinematic is not synonymous with Three.js, but genuine spatial intent may justify R3F/Three/WebGL. Persist spatial intent/mechanism separately from library/provider; stack-aware routing owns implementation choice.

## 15. Typography Impact Pass

Evaluate weight, scale, width/condensation, weight contrast, tracking, casing, line breaking, layering, typography motion and typography × asset relationship.

Detect strong-asset/strong-atmosphere/weak-typography imbalance proactively. Do not convert Typography Impact into a fixed bold-font rule. Preserve readability, hierarchy and explicit mobile behavior.

## 16. Specialized pass gate

```text
candidate
→ specialized pass when applicable
→ PASS | BLOCKED
→ Creative Hypothesis
→ Anti-Cliché
→ Opportunity Prioritization
```

A specialized `BLOCKED` candidate is excluded even when abstract uplift appears high. `NONE` remains valid.

## 17. Motion Dramaturgy Pass

Motion must answer `qual função narrativa o movimento cumpre?`, not merely `tem animação?`.

Classify material motion using `REVEAL | ANTICIPATION | ACCENT | FOCUS_SHIFT | TRANSITION | PROGRESSION | HOLD | RELEASE | AMBIENT | FEEDBACK`.

Design entries, holds, progressions and releases as page dramaturgy. High-intensity motion requires a material narrative point. When expressive demand is high, a page whose entire motion language is generic fade/slide is under-designed.

Scroll-driven motion must be reversible and deterministic when material. If desktop behavior is unsuitable for mobile, explicitly adapt or replace it. Always define a reduced-motion strategy for selected material motion.

## 18. Interaction Opportunity Pass

Interaction exists only when it improves discovery, understanding or perceived impact. Consider scroll scrub, contextual hover, pointer-reactive lighting, drag, hotspots, before/after, progressive technical reveal, sticky storytelling and contextual navigation only when they carry narrative/perceptual value.

`NONE` is a valid result. Pointer/hover-dependent interaction must have a touch/mobile equivalent when preserved or adapted. Selected interaction must define accessibility behavior and safe touch targets.

## 19. Responsive Cinematic Interpreter

> **Responsive não significa preservar o layout. Significa preservar a intenção da experiência.**

Classify relevant mechanisms/elements by viewport as `PRESERVE | ADAPT | REFLOW | REDESIGN | REPLACE | HIDE`.

Desktop-only geometry must not be blindly preserved. A mobile mechanism may be different if it preserves the same intent. Validate safe viewport, touch targets, legibility, performance and reduced-motion handling.

Persist responsive intent and classification in existing Conception State fields so the Prompt Compiler preserves them.

## 20. Cinematic Continuity

Analyze continuity across sections so the page does not become a collection of unrelated premium components.

Candidate visual motifs include `LIGHT | COLOR_ACCENT | LINE | TEXTURE | MATERIALITY | MOTION_SIGNATURE | SHAPE_LANGUAGE | ASSET_DETAIL | TYPOGRAPHY_RHYTHM`.

A motif may return transformed, reduced or reinterpreted. Literal repetition of the hero's dominant effect across most sections is not continuity.

## 21. Intensity Curve / Creative Restraint

Cinematic Budget also governs the page's `INTENSITY CURVE` using `INTENSITY | RELEASE | RECOVERY | RENEWED_EMPHASIS`.

Avoid all sections operating at maximum tension. When multiple high-intensity peaks exist, place release/recovery between them. Concentrate maximum intensity where narrative/perceptual return is highest. Evaluate desktop and mobile separately when needed.

> **Uma landing inteira no máximo perde o máximo.**

## 22. Cinematic Budget / Anti-overcomposition

`CINEMATIC BUDGET` is qualitative governance, not a numeric effect quota.

Classify selected page mechanisms as:

```text
DOMINANT_MECHANISM
SUPPORTING_MECHANISM
ATMOSPHERIC_ACCENT
RECOVERY_ZONE
```

Rules:

- one attention zone should not contain multiple competing dominant mechanisms;
- hero-level intensity must not propagate automatically to every section;
- multi-peak experiences require deliberate recovery/readability zones;
- supporting/atmospheric layers exist to reinforce a dominant idea, not compete with it;
- if the concept is strong but execution is `OVER_COMPOSED`, preserve the concept and remove competing removable layers before redesigning the direction;
- budget is about justified value, never effect count.

The runtime may return explicit `REMOVE_COMPETING_LAYER` recommendations. A material overcomposition blocker prevents cinematic convergence until resolved.

## 23. Stack-aware Cinematic Routing

After perceptual mechanism approval and before committing a library:

```text
approved intent
→ inspect actual repo stack
→ test existing capabilities
→ route to smallest sufficient implementation
→ add dependency only when material
```

Examples:

- Motion/CSS sufficient for local reveal → keep existing stack;
- complex scrub/pinning/cross-element synchronization → GSAP/ScrollTrigger may be justified;
- composition/parallax sufficient → do not introduce Three.js;
- real spatial storytelling → R3F/Three.js may be justified;
- shader only when material/light/distortion genuinely requires shader-level behavior.

Persist approved routes under `TECHNICAL_REQUIREMENTS.cinematicRouting`. Never turn the repertoire into a mandatory stack.

## 24. Generated Media Replacement Strategy

When generated cinematic media is unavailable or not selected, first identify the perceptual values it would have supplied:

```text
ATMOSPHERE
DEPTH
DRAMATIC_LIGHTING
MOTION
COMPOSITION
ASSET_PRESENCE
CINEMATIC_REVEAL
```

Define a deterministic/editorial replacement for every material value where viable. If a material value would disappear with no acceptable replacement, block convergence rather than silently degrading the Web Cinematic baseline.

Generated media remains valid when synthesis is materially superior/necessary. Provider absence alone is never a reason to reduce the experience to a generic static landing.

## 25. Reasoning / Gate Integration

`CINEMATIC_ENRICHMENT` is a governed **subaction**, not a separate hard gate in V1.3.

It inherits one of the current parent actions:

```text
NEW_INTERACTION
RESUME
ENRICHMENT
REFINE
```

Recalculate the parent reasoning profile when real cinematic complexity materially changes. Interrupt the user only when the resulting runtime mismatch/unknown is material.

Do not create a gate for every motion, atmosphere, typography, asset or spatial subpass.

`HIGH INITIATIVE + BOUNDED AUTHORITY` never raises model/effort by itself. Initiative governs proactivity; reasoning capability is governed by actual complexity.
